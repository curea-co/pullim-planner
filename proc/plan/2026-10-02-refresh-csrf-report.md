# 플래너 세션 CSRF 복구 분류 수정 보고

최초 Origin 누락의 원인은 재현하지 못했다. 확인된 결함 두 가지를 수정했다: 세션 클라이언트가 Origin 거부도 토큰 오류로 보고 재시도하던 문제, 그 실패를 플래너 권한 부족으로 오인해 계정 조회와 추가 refresh를 유발하던 문제다.

`CSRF_TOKEN_MISMATCH`만 토큰 재취득 후1회 복구한다. `CSRF_ORIGIN_REJECTED`는 재시도하지 않으며, 두 CSRF 실패가 세션 복원에 전파되면 기존 연결 오류 UI로 전달한다. 실제 권한403은 기존 동작을 유지한다. 공유 helper로 도메인/세션 판정을 통일했다.

전체497테스트·타입·lint·build 통과. lint는 기존 경고2개/오류0이다. 세부 및 재현 한계는 [계획·검증 기록](2026-10-02-refresh-csrf.md)을 참조한다. API Origin 방어·토큰·쿠키 설정·Content-Type은 변경하지 않았다.

실 UI mock 브라우저에서 Origin 거부→연결 오류(추가 계정 조회 없음), 토큰 불일치→1회 복구 후 홈, 실제 권한 거부→기존 안내를 모두 확인했다. 사용자 승인 범위에서 PR을 진행하며 개발 배포는 CI·리뷰 통과 후 수행한다. 최초 Origin 누락 자체를 재현하거나 해결했다고 주장하지 않는다.
