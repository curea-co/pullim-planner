## 상태 모델 (`useAuth`)

- `status`: `'loading' | 'authenticated' | 'unauthenticated'`
- `user`: `AuthUser | null`
- `login(input)`, `signup(input)`, `logout()`, `checkEmail(email)`
- 부트스트랩: 마운트 시 access token 있으면 `me()` 호출(401→refresh 자동). 성공→authenticated,
  실패/무토큰→unauthenticated. 해결 전까지 loading.
- 세션 만료(`onSessionExpired`): unauthenticated 전환 + `/login` 이동.

## 가드 (RequireAuth)

- `loading` → 중앙 스피너(하이드레이션 깜빡임 방지: authenticated 확정 전 본문 미렌더)
- `unauthenticated` → `router.replace('/login')` + null 렌더
- `authenticated` → children
- `/login`·`/signup`에서 이미 authenticated면 `/`로 replace (Container에서 처리)

## 검증 규칙 (BE DTO 정렬)

- 이름: 1~100자, 비어있지 않음
- 이메일: `IsEmail` 형식. 회원가입은 blur 시 `checkEmail`로 중복 안내(확정은 submit conflict)
- 비밀번호: 8~64자 + 영문·숫자·특수문자 각 1개 이상 (`PASSWORD_PATTERN`)
- 비밀번호 확인: 일치
- 서버 에러(`ApiError.code`): `conflict`(이메일 중복)·`validation_failed`·`unauthorized`(로그인 실패) 별 메시지 매핑, 그 외 toast

## 반응형 / 모션 / a11y

- 반응형: 중앙 카드 `w-full max-w-sm`, 모바일 좌우 패딩. 카드 내부는 단일 컬럼 스택.
- 모션: 과함 지양. 입력 포커스/버튼은 기존 토큰 트랜지션만. 제출 시 버튼 로딩 상태.
- a11y: `<label htmlFor>` 연결, 에러는 `aria-invalid`+`aria-describedby`, 제출 버튼 `disabled`(로딩),
  비밀번호 표시 토글 `aria-pressed`/`aria-label`.
